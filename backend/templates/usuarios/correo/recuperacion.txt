   CUERPO DEL CORREO EN TEXTO PLANO.

   Variables disponibles (las entrega PasswordResetForm.save()):
     user            -> el objeto Usuario destinatario
     email           -> su correo electrónico
     uid             -> su id codificado en base64 seguro para URL
     token           -> la firma temporal
     protocol        -> "http" o "https" (según request.is_secure())
     domain          -> el dominio del sitio
     site_name       -> nombre del sitio
   Más las que agregamos en extra_email_context (nombre_sistema,
   correo_soporte, minutos_validez).

   ¿Por qué {% autoescape off %}?
   Django escapa las variables por defecto para prevenir XSS en HTML. En un
   correo de TEXTO PLANO eso es contraproducente: un apellido como "O'Higgins"
   se mostraría como "O&#x27;Higgins". Aquí no hay HTML que pueda ejecutarse,
   así que desactivarlo es correcto. En la versión HTML del correo NO se
   desactiva.

   ¿Por qué se envía también en texto plano si ya existe la versión HTML?
   Porque muchos clientes de correo corporativos bloquean el HTML por
   seguridad, y algunos lectores de pantalla trabajan mejor con texto. El
   mensaje viaja con ambas versiones y cada cliente elige la que puede mostrar.
   ========================================================================= {% endcomment %}
